# pyboard_LEDRingTestV0.1 — 迁移评估与实现规划

> 目标：将 `LEDRing_for_unity_byte_mode_NewVersion_V2_4.ino`（Arduino Due / SAM3X8E）迁移到 **pyboard v1.1（STM32F405）** + MicroPython。
> 本文档为规划文档，涵盖：资源分配表、项目结构、核心差异模块的实现对照。
>
> **状态更新（V0.1 已实现）**：首版可运行工程已落地到本目录，代码清单见文末【附录 A】。给水/OG 采用**硬件 one-pulse(OPM) 单脉冲**模式（非 PWM 波形，等价"100% 占空比单次脉冲"），引脚集中配置于 `config.py`。

## 0. 迁移总体结论（回顾）

| 维度 | 结论 |
|------|------|
| 整体复杂度 | 中等偏上（4/5），逻辑可 100% 等价实现 |
| 通讯 | 走 **USB CDC (VCP)**，与 Due `SerialUSB` 对等；协议字节完全兼容，Unity 端协议解析**零改动** |
| 给水/OG 定时 | 改用 **`pyb.Timer` 硬件 PWM / one-pulse**，硬件自动翻转，±1μs 级，CPU 不参与 |
| 光功率 | 改用 **`pyb.DAC`**（X5/X6，12-bit，0–3.3V） |
| 中断优先级 | 不作为硬约束，用 `pyb.ExtInt` + 主循环标志位模型即可 |
| 多核 | STM32F405 单核，无真多核；用"硬件中断 + 主循环"模型，不用 `_thread` 做实时控制 |
| 部署方式 | 最终部署走 `main.py` 上电自动跑（禁用 REPL）；开发调试可用 REPL/`exec` 临时跑 |

### 1.2 光功率 DAC（关键：必须真 DAC）

- pyboard v1.1 有 **2 路 12-bit DAC**：`X5`(PA4, DAC1)、`X6`(PA5, DAC2)。
- 输出范围 **0–3.3V**（实测 buffer 模式下约 0.2mV–3.27V，线性度良好）。
- 精度 12-bit（0–4095），与 Arduino Due `analogWriteResolution(12)` **完全一致**。
- 原代码映射：`lightControl`（0–4096）→ `dac.write(min(value, 4095))`。
- **冲突**：上表给水泵 4 建议用 X6，与 DAC2 冲突。**结论：光功率固定占用 `X5`(DAC1)，给水泵 4 改用其他 PWM 引脚**（见 1.3 重分配）。

### 1.3 定时器 / PWM 通道分配（给水 + OG）

**核心原则**：给水与 OG 需要"单次精确脉冲"，用硬件 PWM/one-pulse 实现，硬件比较器自动拉高/拉低，CPU 不参与。

STM32F405 有 14 个定时器（TIM1–TIM14），每个定时器 4 个通道（部分无）。分配建议如下（**每个引脚占 1 个定时器通道**，通道内 PWM 独立）：

| 定时器 | 通道 | pyboard 引脚 | GPIO | 用途 |
|-------|------|-------------|------|------|
| Timer(5) | CH1 | `X1` | PA0 | 给水泵 0 |
| Timer(5) | CH2 | `X2` | PA1 | 给水泵 1 |
| Timer(5) | CH3 | `X3`* | PA2 | 给水泵 2（若泵2用X3） |
| Timer(5) | CH4 | `X4`* | PA3 | 给水泵 3 |
| Timer(8) | CH1 | `Y3`? | PB8 等 | 给水泵 4/5/6/7 |
| Timer(2) | CH1 | `X9` | PB6 | OG 光遗传 |
| Timer(2) | CH2 | `X10`? | PB7 | (备用) |

> **说明**：定时器与引脚有固定的硬件复用（alternate function）关系，需按 pyboard 官方 `AltMode` 表配对。上表为逻辑规划，**最终要按「每个泵一个 PWM 通道、互不抢定时器」的原则，用 `Pin.af_list()` 实测每根接线支持的定时器通道后再定稿**。开发首版（V0.1）可先只启用泵 0/1 + OG，其余泵后续扩展。

**one-pulse 实现思路（给水泵）**：

```python
# 逻辑伪代码：硬件单脉冲，高电平持续 micros 微秒后自动回落
from pyb import Timer, Pin

pump_pin = Pin('X1', Pin.OUT_PP)
t = Timer(5, freq=100_000)            # 100kHz 计数基准
ch = t.channel(1, Timer.PWM, pin=pump_pin)

def pump_set(micros):
    # 思路A：pulse_width 直接设高电平微秒数（硬件比较输出）
    ch.pulse_width(micros)
    # 思路B（更严谨的 OPM）：配置单脉冲模式后软件触发，硬件自动完成整个脉冲
    #   （用 stm 寄存器 TIMx_CR1.OPM，触发后用 DMA/更新事件自动关断）
```

### 1.4 ExtInt 外部中断分配（传感器）

`pyb.ExtInt` 使用 STM32 的 EXTI 线（EXTI0–EXTI15），**同一 GPIO 编号的引脚不能同时做两个独立中断**（如 PA2 与 PB2 冲突，都占 EXTI2）。分配时需保证每个传感器的 GPIO 编号不同。

| 传感器 | 建议引脚 | GPIO | EXTI 线 | 触发沿 |
|-------|---------|------|---------|--------|
| 舔水 0 | X3 | PA2 | EXTI2 | RISING |
| 舔水 1 | X4 | PA3 | EXTI3 | FALLING（leave） |
| 红外门控 | X11 | PB4 | EXTI4 | FALLING |
| 压杆 | X12 | PB5 | EXTI5 | FALLING |
| 同步 | — | PB0 | EXTI0 | CHANGE |
| 舔水 2–7 | 预留，避开已占 EXTI 编号 | — | — | — |

> **中断回调只做轻量操作**（记录 `ticks_us()` 时间戳 + 置 flag），帧组装放主循环，避免中断里做耗时操作。

### 1.5 通讯接口分配

| 用途 | pyboard 外设 | 说明 |
|------|-------------|------|
| 与 Unity 上位机通讯 | `pyb.USB_VCP`（USB CDC） | 与 Due `SerialUSB` 对等，一根 USB 线直连 |
| 调试 REPL（开发期） | 挪到 `UART(2)`（X3/X4）或其禁掉 | 部署时 `os.dupterm(None)` 禁用 USB REPL |

## 3. 与 Arduino 差异最大的模块 — 实现对照

### 3.1 定时器：`DueTimer` → `pyb.Timer` 硬件 one-pulse

**Arduino（原）**：
```cpp
DueTimer pumpTimer = Timer.getAvailable();
// 软件置高 + 定时器中断置低（中断参与，微秒级有调度抖动）
void pump_set(int pump_pin, int micros, bool write_mode=true){
  digitalWrite(pump_pin, HIGH);
  active_pin = pump_pin;
  pumpTimer.attachInterrupt(pump_set_call_by_interrupt).start(micros);
}
void pump_set_call_by_interrupt(){
  digitalWrite(active_pin, LOW);
  pumpTimer.stop();
}
```

**MicroPython（硬件 one-pulse，优于原实现）**：
```python
# hal_timer.py
from pyb import Timer, Pin

class PumpPulse:
    """单次精确给水脉冲：硬件比较器自动拉高->拉低，CPU 不参与"""
    def __init__(self, tim, ch_num, pin):
        self.timer = Timer(tim, freq=100_000)   # 100kHz 基准（10us 粒度）
        self.ch = self.timer.channel(ch_num, Timer.PWM, pin=Pin(pin))
    def fire(self, micros):
        # 方式1：直接设高电平宽度（微秒）
        self.ch.pulse_width(micros)
        # 方式2（更严格 OPM）：配置 CR1.OPM 单脉冲，触发后硬件自动停表

class OGPulse(PumpPulse):
    """OG 光遗传：与给水同构，只是时长单位为毫秒"""
    def fire_ms(self, ms):
        self.fire(ms * 1000)
```

**关键差异**：
- Arduino：拉高靠 CPU `digitalWrite`，拉低靠中断回调 → 两端都有延迟/抖动。
- MicroPython：拉高+拉低全靠硬件比较输出 → **±1μs，无中断、无 GC 影响**。

### 3.2 DAC：`analogWrite` 12-bit → `pyb.DAC`

**Arduino（原）**：
```cpp
pinMode(OGLIGHTPOWERPIN, OUTPUT);
analogWriteResolution(12);
analogWrite(OGLIGHTPOWERPIN, lightControl);  // 0~4096
```

**MicroPython**：
```python
# hal_io.py
from pyb import DAC
og_dac = DAC(1, bits=12)          # DAC1 = X5，12-bit

def set_light_power(value):
    og_dac.write(int(min(max(value, 0), 4095)))  # 0~4095 -> 0~3.3V
```

**关键差异**：
- 引脚 66（Due）是 DAC，pyboard 用 X5（DAC1），硬件 0–3.3V，分辨率一致（12-bit）。
- Arduino 需 `pinMode` + `analogWriteResolution` 两步；MicroPython `DAC` 一行搞定。

### 3.3 外部中断：`attachInterrupt` → `pyb.ExtInt`

**Arduino（原）**：
```cpp
attachInterrupt(digitalPinToInterrupt(readLickPins[0]), LickReportInInterrupt0, RISING);
void LickReportInInterrupt0(){
  char entry[16]; strcpy_P(entry, msg);
  bufferPushChar(entry);   // 中断里直接拼字符串+推缓冲（较重）
  lick_count[0]++;
  ExecuteWhenLicking(0);
}
```

**MicroPython（更符合"轻量中断"原则）**：
```python
# hal_io.py
from pyb import ExtInt, Pin
import utime

lick_flags = [0]*8
lick_ticks = [0]*8
lick_count = [0]*8

def _lick0(_line):
    lick_flags[0] = 1                       # 只置标志
    lick_ticks[0] = utime.ticks_us()        # 只记时间戳
    lick_count[0] += 1
    # 主循环里再组装 "li:0:1" 帧，避免中断里拼字符串

ext0 = ExtInt(mapping['lick0'], ExtInt.IRQ_RISING, Pin.PULL_UP, _lick0)
```

**关键差异**：
- Arduino 中断里拼字符串+推缓冲（其实也偏重）；MicroPython 建议中断里**只置标志+时间戳**，主循环组装发送，实时性更稳、代码更清晰。
- `digitalPinToInterrupt` 的手动接线换成 `ExtInt` 的 `IRQ_RISING/FALLING/CHANGE` 常量。

### 3.4 发送帧：`String` + 缓存前缀 → `bytes`/`struct`

**Arduino（原）**：
```cpp
size_t stringToByteArray(String inputStr, byte* outputArray){
  // 输出: [0xAA][typeId][len][content...][0xDD]
  outputArray[0]=0xAA; outputArray[1]=typeId; outputArray[2]=contentLength;
  ...; outputArray[3+len]=0xDD; return 4+len;
}
```

**MicroPython（字节级一致）**：
```python
# protocol.py
SERIAL_PRINT_TYPE = ["li","en","pr","ci","log","echo","vc","cmd","debugLog","st","si","ms"]

def encode_frame(type_str, content: str) -> bytes:
    tid = SERIAL_PRINT_TYPE.index(type_str)          # typeId 必须与数组下标一致
    body = content.encode("ascii")[:0xff]
    return b"\xaa" + bytes([tid, len(body)]) + body + b"\xdd"

def decode_frame(data: bytes):
    # data = [typeId][len][content...]  （已剥离 0xAA/0xDD 头尾）
    tid, n = data[0], data[1]
    return tid, data[2:2+n].decode("ascii")
```

**关键差异**：Arduino 用 `String` 频繁动态分配（易碎片化/慢）；MicroPython 用不可变 `bytes` + `struct`，更直接、更快，且**typeId 顺序必须严格对齐**（`li=0, en=1, ...`）。

### 3.5 接收解析：`isRecording` 状态机 → 同构的 Python 状态机

**Arduino（原）**：`0xAA` 起始 → 收数据 → `0xDD` 结束，中间 `0x2f` 触发文本命令。

**MicroPython**：逻辑完全相同，只是用 `bytes` 缓冲 + 状态标志：

```python
# hal_uart.py
def parse_stream(read_byte):
    global is_recording, buf, plain_mark
    b = read_byte()
    if not is_recording and b == 0xAA:
        is_recording = True; buf = bytearray()
    elif not is_recording:
        if b == 0x2f:
            if not plain_mark:
                plain_mark = True
            else:
                cmd = read_line()            # 读一行文本命令
                command_parser.run(cmd)
                plain_mark = False
    else:
        if b == 0xDD:
            command_parser.run(decode_frame(buf))
            is_recording = False
        elif b == 0xAA:
            buf = bytearray()
        else:
            buf.append(b)
```

### 3.6 双缓冲发送：`RingBuf` + `DoubleBuffer` → `deque`/`bytearray` + 锁

**Arduino（原）**：`DueTimer` 中断 + `noInterrupts()` 保护读写指针。

**MicroPython**：
- 中断里只写 flag/time，不直接推缓冲；主循环组装帧后放入 `collections.deque` 或 `bytearray` 发送队列。
- 若仍需中断直写缓冲，用 `pyb.disable_irq()/enable_irq()` 做临界区（等价 `noInterrupts()`）。
- MicroPython 的 GC 可能不定时暂停，**发送缓冲要预留余量，避免 GC 阻塞导致溢出**。

### 3.7 状态变量指针表：`pointer_array` → dict 映射

**Arduino（原）**：用 `int* pointer_array[]` 索引到变量，命令 `0=1` 按序号写值。

**MicroPython**：用 **有序索引 dict** 保持序号契约：

```python
# state.py
# 索引序号必须与上位机约定一致（0~10）
STATE_ORDER = ["lick_mode","trial","trial_set","now_pos","lick_rec_pos",
               "INDEBUGMODE","OGActiveMills","miniscopeRecord",
               "waterServeWhenLick","waterServeManual","lightControl"]
state = {"lick_mode":0, "trial":0, ...}

# command_parser 中：state[STATE_ORDER[var_idx]] = value
```

**关键差异**：Arduino 靠指针数组实现"可变变量表"，MicroPython 用 dict + 固定键顺序列表更清晰，且**序号契约保持不变**。

## 4. 迁移风险与验证清单

- [ ] **给水微秒精度**：用示波器验证 one-pulse 高电平宽度是否 = `waterServeMicros`（目标 ±1μs）。
- [ ] **DAC 0–3.3V**：验证 `lightControl` 0→0V、4095→3.3V 线性。
- [ ] **协议字节级一致**：抓包对比 Arduino 帧 vs MicroPython 帧（`0xAA typeId len ... 0xDD` 完全一致）。
- [ ] **握手**：`initialed:V2.4` → 收 `ACK` → 回 `ACK_OK`；确认禁用 REPL 后无横幅/回显污染。
- [ ] **typeId 与变量索引契约**：`serial_print_type` 下标、`pointer_array` 0–10 序号、数组类型编号，与 Unity 端严格一致。
- [ ] **ExtInt 编号不冲突**：同一 GPIO 编号的引脚不能同时做两个中断。
- [ ] **定时器通道不冲突**：每个泵/OG 独占一个定时器通道（用 `Pin.af_list()` 实测）。

## 附录 A —— 首版可运行工程代码清单（V0.1）

> 按"配置 / 通讯 / 主程序"三块组织（boot 与 main 不合并，同属主程序块）：

| 文件 | 所属块 | 职责 | 对应原 Arduino 代码 |
|------|--------|------|-------------------|
| `config.py` | 配置 | 引脚映射、协议常量契约（typeId、变量索引、缓存前缀） | 常量定义区 / 宏 |
| `comm.py` | 通讯 | 帧编解码、USB_VCP/UART 收发、握手、接收状态机、发送缓冲 | stringToByteArray / ByteArrayToCommand / SerialUSB / 握手 / loop 接收循环 / RingBuf |
| `boot.py` | 主程序（启动项） | 上电配置 USB 模式、迁移/禁用 REPL（不与 main 合并） | （Arduino 无对应） |
| `main.py` | 主程序 | 硬件驱动（GPIO/ExtInt/DAC/one-pulse）+ 状态业务 + 命令解析 + 主循环 | setup() + loop() + DueTimer + attachInterrupt + analogWrite + commandParse + TrialStart/End |

**关键实现说明**：
- 给水/OG 输出采用**硬件单脉冲**（`pyb.Timer` PWM 通道 + `pulse_width()` 一次触发即回落），**不是周期性 PWM 波形**，等价于"100% 占空比的单次脉冲"，CPU 不参与翻转，精度 ±1μs 级。
- 引脚全部集中在 `config.py`，改一行即可重映射。
- 定时器/通道分配表 `_PUMP_TIMER_CH`、`_OG_TIMER_CH` 在 `main.py`，需上板后用 `af_list()` 实测校正。
- REPL 在 `boot.py` 中迁移到 UART2，USB VCP 交由 `comm.py` 独占，避免横幅/回显污染。
